# Demo script

This is a release aid, not a claim that a demo has already been recorded.

## Objective

In 35–50 seconds, demonstrate that a single owner can publish one article through the direct workflow. A browser fallback, if the embedding app has one, is outside the recording scope.

## Recording sequence

1. Open the app on an already authenticated, disposable test account. Do not record QR codes, account names, avatars, cookies, or browser extensions.
2. Select **Article** and show a short, non-sensitive title and body. Use one harmless test image whose source can be published.
3. Start the publish action and show the sequential progress states: draft, media staging, save, submit, fresh verification.
4. Open the resulting article in a clean browser tab and show only the article title and public URL area after masking account identity.
5. End on the repository name and the one-line positioning: a focused CLI for direct HTTP publishing of one Weibo headline article.

## Editing rules

- Blur every identifier: account name, UID, QR code, cookies, request headers, local paths, timestamps if correlatable, and browser-profile details.
- Do not show developer tools, network request details, endpoint URLs, payloads, anti-bot responses, or recovery logic.
- Use a disposable article and remove it after recording if the platform allows it.
- Use captions for the workflow states; a silent GIF can be the README preview and the fuller MP4 can be a release attachment.

## Evidence to retain privately

- Recording source, its masking review, and the test date.
- A one-line outcome record: success, rejected, or indeterminate.
- The exact public-repo commit used in the recording.
